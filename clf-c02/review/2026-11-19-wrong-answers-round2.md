## 신규 오답

### d2-033 | CPU 80% 초과 시 알림
- **정답:** CloudWatch / **내 답:** CloudTrail

| 서비스 | 질문 | 대상 | 예시 |
|---|---|---|---|
| **CloudWatch** | "**얼마나**?" (성능) | 메트릭·로그·알람 | CPU 80% 알람 → SNS 알림 |
| CloudTrail | "**누가** 무엇을?" (감사) | API 호출 이력 | 누가 EC2를 종료했나 |
| AWS Config | "설정이 **어떻게** 바뀌었나?" | 리소스 구성 변경 | SG 규칙 변경 이력 |

> 💡 실무 비유: CloudWatch = Zabbix/Prometheus 모니터링, CloudTrail = 접근 감사 로그(audit.log)

### d3-005 | 가용 영역(AZ) 정의
- **정답:** 하나 이상의 개별 데이터 센터로 구성, 같은 리전의 다른 AZ와 물리적으로 분리
- **내 답:** 여러 리전을 묶은 지리적 단위 ← 계층을 거꾸로 이해

```
리전 (Region, 예: ap-northeast-2 서울)
 ├─ AZ-a  ── 데이터 센터 1개 이상
 ├─ AZ-b  ── 데이터 센터 1개 이상   ← AZ끼리 물리적 분리, 저지연 네트워크 연결
 └─ AZ-c  ── 데이터 센터 1개 이상
```

- 포함 관계: **리전 ⊃ AZ ⊃ 데이터 센터** (리전을 묶는 상위 단위는 없음)
- 엣지 로케이션: CloudFront 캐시용, 리전/AZ와 별개
- 고가용성 = **Multi-AZ**, 재해 복구 = **Multi-Region**

### d3-003 | 코드에서 AWS API 호출
- **정답:** AWS SDK / **내 답:** AWS Artifact

| 도구 | 용도 |
|---|---|
| **AWS SDK** | 코드 안에서 API 호출 (Python = boto3, Java SDK 등) |
| AWS CLI | 터미널/쉘 스크립트에서 호출 |
| CloudFormation / CDK | 인프라를 코드로 정의(IaC) |
| AWS Artifact | **규정 준수 보고서**(SOC, PCI, ISO) 다운로드 포털 ← 개발 도구 아님 |

> 💡 Artifact = "감사 문서함". 이름에 속지 말 것 (빌드 산출물 저장소 아님 → 그건 CodeArtifact).
